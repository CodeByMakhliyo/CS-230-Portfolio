# CS-230-Portfolio
CS-230-Software Design Portfolio

CS 230 Module Eight Journal Reflection
1. Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was the client for this project. They wanted to expand their Android game, Draw It or Lose It, into a web-based application that could support multiple platforms and users. The application needed to support multiple teams and players, keep game and team information organized, and ensure names and IDs were unique. The software also needed to be reliable, secure, and able to support multiple users at the same time.

2. What did you do particularly well in developing this documentation?

I think I did well explaining the software requirements and comparing different operating platforms. I also did a good job identifying Linux as a strong choice for the server because of its stability, security, and flexibility. The design document helped organize the requirements, system architecture, operating platform recommendations, and security considerations in one place.

3. What about the process of working through a design document did you find helpful when developing the code?

The design document helped me understand what the application needed before writing the code. It gave me a clear idea of the classes, relationships, and requirements to implement. This made it easier to connect the design to the actual Java code. Creating the design first also helped reduce confusion because I could use the document as a reference while developing the application.

4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my work, I would improve the section about the application's architecture and cloud-based deployment. I would explain more about how the application could be designed for a cloud environment and how services such as storage, scaling, and security could be managed. This would make the design more useful for a modern application that may need to support a large number of users.

5. How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?

I interpreted the user's needs by focusing on the requirements provided by The Gaming Room and considering how players and users would use the application on different platforms. I used those requirements when making decisions about the application's structure, unique identifiers, security, and operating platform. Considering user needs is important because the software must solve the client's actual problem. A technically good application will not be successful if it does not meet the user's expectations or requirements.

6. How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

I approached the design by first identifying the client's requirements and then breaking the application into smaller components. I considered the classes, relationships, operating platform, security, and overall architecture before implementing the code. I also used design patterns such as Singleton and Iterator when appropriate. In the future, I would continue using requirements analysis, UML diagrams, design patterns, and platform comparisons before starting development. I would also consider cloud and serverless options earlier in the design process because scalability and cost are important for modern applications.
